# CARD_ART_STYLE_LOCK · 正式卡面美术生产基线（v1 冻结）

> 本文档是《宵月秘藏》剩余 70 张正式卡面美术**唯一的视觉生产基线**。
> 由 8 张试制牌（愚者 / 恋人 / 死神 / 世界 / 权杖王牌 / 圣杯二 / 宝剑三 / 星币国王）验证后冻结。
> 量产前任何与本文件冲突的实现，以本文件为准；修改本文件需要人工确认。

---

## 1. 项目视觉定位

一句话：**「魔女书房里收藏的旧银秘仪牌」**——不是「漂浮在宇宙中的发光圣物」。

物质感优先级：纸张 > 金属（旧银/黄铜）> 珐琅 > 墨线 > 手绘痕迹。
明确弱化：能量体、水晶、科幻 UI、纯数字宇宙、发光 bloom。

## 2. 月章插画规范（22 张通用）

- 画窗：牌面坐标 `x10 y63 w80 h110`（viewBox 100×232 内），插画按 `xMidYMid slice` 裁切；
- 源文件画幅：**300×420**（与画窗同比例 8:11 ±2%，避免显著裁切）；
- 统一元素：深靛纸底（每张可用同族渐变，禁用星云质感）、银线墨稿、单一叙事光源、月窗铭号/星轨饰带/真名带/火漆均由牌框层负责（见 §11）；
- 主体层级：一个主视觉 + ≤2 个次级象征；人物以**剪影/侧影**呈现，不画正脸五官特写；
- 明度结构：画面 60% 以上处于深部，光源与主体亮部合计不超过 25%。

## 3. 星签插画规范（56 张通用）

- 画窗：`x12 y38 w76 h84`（viewBox 100×160 内）；源文件画幅 **300×340**；
- 复杂度必须低于月章：一个主体 + 至多一个次级元素；
- 角标编号（A/二…十/侍骑后王）、真名带、火漆点由牌框层负责；
- 宫廷牌人物同样使用剪影+侧影语言，不绘制具体面孔。

## 4. 四花色差异（家族语言）

| 花色 | 环境语汇 | 线稿倾向 | 辅助符号 |
| --- | --- | --- | --- |
| 权杖·火 | 木、焰、烬、出发行旅 | 上升斜线、焰口曲线 | 余烬星点、束布、新叶 |
| 圣杯·水 | 容器、水岸、倒影、潮 | 横向波弧、圆拱 | 双月、水纹 pattern、香蒲 |
| 宝剑·风 | 云、雨、夜空、决断 | 垂直锋线、雨丝排线 | 云涡、落星 |
| 星币·土 | 田垄、堡楼、藤蔓、工艺 | 水平垄线、紧密短弧 | 环璧纹、谷苗、城堡剪影 |

同花色 14 张共享环境语汇；数字等级以「主体数量/规模」体现，不以颜色区分。

## 5. 主色控制

- 全系底色：玄夜靛黑 `#0D1226` ~ 靛蓝 `#1B2347` 一族（花色可微调色温：权杖暖、圣杯青、宝剑冷、星币绿）；
- 墨线：旧银 `#C7CEDD`（亮部）/ `#8A93AD`（暗部排线）；
- **每张牌一个主光色**（accent，数据层已有）：只用于叙事光源 + 一个关键象征物；
- 月金 `#E6C687` 仅限世界/太阳/国王级；大面积金色禁止；
- 饱和度纪律：任何一张牌，主光色覆盖面积 ≤15%。

## 6. 材质

- 纸：深靛底 + 极细网格/排线 pattern（如 `wld-grid`），禁用噪点滤镜堆砌；
- 金属：哑光双线勾勒（旧银/黄铜 `#B28C4F`），高光只用 1px 亮线，禁用渐变抛光；
- 珐琅：小面积实色点彩（≤3px 半径的圆点/菱形）；
- 墨线：`<pattern>` 排线做阴影（hatch 间距 6–9，透明度 0.3–0.5）。

## 7. 光源

- **每张牌有且仅有一个叙事光源**（数据层 accent 对应）；
- 光可以来自：烛、灯、焰、窗、晨星、月、水面反光——**不来自牌框、不来自"能量"**；
- 辉光半径 ≤ 主体尺寸的 1.5 倍，中心不透明度 ≤ 0.5；
- 禁止：全画面 bloom、边缘泛光、四角发光。

## 8. 构图

- 月章：主视觉占画窗 50–70%，重心每张不同（上/中/下轮换），连续四张不重复同一重心；
- 星签：主体占 55–75%，居中或单侧；
- 视线动线：光源 → 主体 → 铭文带方向引导；
- 留白：至少 20% 面积保持深底安静区。

## 9. 人物设计原则

- 剪影/侧影/背影优先；如需面部只给鼻梁与下颌线，不画眼睛细节；
- 服饰为"时代不明的仪式长袍/旅装"，纹饰使用本体系符号（月相/星点/掐丝回纹）；
- **禁止**：二次元大眼角色、浮现式立绘、角色周边式装饰、任何具体作品的角色特征（发型/制服/挂件/元素标）；
- 人体比例可略拉长（8 头身内），保持版画感。

## 10. 背景设计原则

- 背景是"书房内的纸"或"牌面世界里的一处实地"，不是宇宙；
- 允许：远山、云、星（少量、小）、雨、水面、建筑剪影、手稿网格；
- 禁止：占画面 >30% 的星云、行星、环形轨道、漂浮 debris。

## 11. 牌框与插画分离（硬性工程规则）

- 插画 = 独立 SVG 文件（`src/assets/cards/{major,minor}/`），**只画画窗内容**；
- 牌框/铭号/饰带/真名带/火漆 = `ui/CardArt.tsx` 矢量层，永不焊进插画；
- 接入 = 在 `src/tarot/artwork.ts` 的 `FILE_BY_CARD` 增加一行映射，组件零改动；
- 画窗内允许叠加一圈 0.6–0.7 银线"图版框"（版画图版感）。

## 12. 文件格式

- 一律 **SVG**（矢量、无损缩放、当前单张 4.5–6.5KB）；
- 位图仅当未来引入手绘/生成位图时允许 WebP（上限 250KB/张，`loading="lazy"`），本轮未使用。

## 13. 分辨率

- 源画幅：月章 300×420、星签 300×340（逻辑像素）；
- 画窗最大显示尺寸（详情页 250px 宽）下等效 ≥2× Retina 覆盖，缩略图 96–110px 下 ≥3×；
- 若未来提升：源画幅翻倍即可，接口不变。

## 14. 文件命名

```
src/assets/cards/major/major-{NN}-{slug}.svg     # major-00-the-fool
src/assets/cards/minor/minor-{suit}-{rank}.svg   # minor-cups-2, minor-pentacles-14
```
slug 全小写连字符；rank 用数字（1=A，11=侍从，12=骑士，13=王后，14=国王）。

## 15. 禁止使用的视觉元素

1. 冰蓝晶体卡框 / 半透明玻璃牌
2. 外边框 bloom / 整牌泛光
3. 紫蓝星云占主体
4. 大型环形轨道 + 漂浮星体作背景主体
5. 漂浮宇宙舞台
6. 白色尖拱浮雕框
7. 牌名悬浮牌体外作为主承载
8. 剪纸舞台盒拼贴
9. 未获得态做成发光空壳（保持火漆封缄）
10. 飘带横幅式底部装饰

## 16. 去原神化硬约束

- 不使用原神角色式发型/服装/神之眼挂件/元素图标/国家文化符号；
- 不使用原神 logo、纹章、字体、UI 图案；
- 不做截图抠图、image-to-image、换皮改造；
- 风格描述只用艺术运动/时期/材质/媒介（如"铜版蚀刻""新艺术"），**禁止 "in the style of 具体在世/近现代艺术家"**。

## 17. 「恋人」专项约束

禁止出现（对应月谕圣牌恋人已见表达）：剧院盒式空间、相框墙、乌鸦、枯枝横穿、共舞人物姿态、红幕色彩组织、底部飘带。
本作锚定构图：**共根双生植物 + 两条独立星轨 + 未触之光隙**。量产近似主题牌（圣杯二等）时沿用"关系=并置与呼应"的表达，不使用拥抱/共舞。

## 18. 「世界」专项约束

禁止：紫蓝星云 + 发光圆环 + 悬浮人物/卡牌的任何两两组合。
本作锚定构图：**黄铜星盘（哑光仪器）+ 刻绘世界图谱盘 + 桂冠合抱 + 中心小舞者剪影 + 手稿网格底**。环=画出来的仪器，不是光。

## 19. 后续 70 张量产规则

1. 逐张先填「设计记录」（模板见 ART_PILOT_8_CARDS.md），再动手画；
2. 每完成 4 张做一次并排一致性检查（同花色/同等级混看）；
3. 每张必须能回答："它的光从哪来？它的 accent 用在哪一个象征物上？";
4. 数字牌优先复用同花色环境语汇，换主体不换世界；
5. 宫廷牌统一"剪影+权杖/杯/剑/币持物+等级冠饰"三件套；
6. 任何一张让复审者产生"这是某成熟游戏同人"的直觉 → 打回重做，不做微调辩护。

## 20. 偏离系列风格的判定清单

一张新牌若命中 ≥2 条，视为偏离：
- [ ] 主光色不止一个 / 光源方向与全组顶光逻辑冲突
- [ ] 出现体系外高饱和色块
- [ ] 人物五官清晰可见（非剪影/侧影）
- [ ] 背景出现星云/行星/环形轨道
- [ ] 材质出现水晶/能量/全息质感
- [ ] 缩略图 96px 下无法辨认花色或主体
- [ ] 与已有正式牌并排时"像别人的游戏"

## 21. 替换程序化 fallback 的技术方法

1. 产出 SVG → 放入 `src/assets/cards/{major|minor}/`，按 §14 命名；
2. 打开 `src/tarot/artwork.ts`，在 `FILE_BY_CARD` 增加 `cardId: 文件基名`；
3. 完成。`CardArt` 自动切换正式插画，未登记的牌继续使用程序化纹章；
4. 运行 `pnpm test`（artwork 注册表测试会校验 id 合法性与 URL 存在）。
   —— 全程无组件改动、无 8 个 if、无存档/抽牌逻辑影响。
